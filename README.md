# TAOCP exercise 7.2.2.8--89: formal proofs of nonexistence

Exercise 89 of Pre-Fascicle 9B of *The Art of Computer Programming* asks for which triples
`(u, v, w)` with `u^2 + v^2 = w^2` a discrete four-piece rookwise connected dissection of a
`w × w` square into `u × u` and `v × v` squares exists. This repository proves in Lean 4 that none
exists for five triples.

**Status: `(20, 21, 29)`, `(28, 45, 53)`, `(40, 42, 58)`, `(33, 56, 65)` and `(48, 55, 73)` are all
proved, with no `sorry`. Each proof depends on one axiom generated by `native_decide`, as explained
under [Trust](#trust).**

### Motions

A motion is a symmetry of the `w × w` square followed by an integer shift. This is the form
`α β` of the text of Section 7.2.2.8.

```lean
/-- A symmetry of the square, given by an optional swap of coordinates and two optional flips,
followed by a shift. -/
structure Motion where
  sw : Bool
  fx : Bool
  fy : Bool
  dx : Int
  dy : Int

/-- First coordinate of the image of cell `(x, y)` of the `w × w` square. -/
def Motion.imgX (m : Motion) (w : Nat) (x y : Nat) : Int :=
  (if m.sw then (if m.fy then (w : Int) - 1 - y else y)
   else (if m.fx then (w : Int) - 1 - x else x)) + m.dx

/-- Second coordinate of the image of cell `(x, y)` of the `w × w` square. -/
def Motion.imgY (m : Motion) (w : Nat) (x y : Nat) : Int :=
  (if m.sw then (if m.fx then (w : Int) - 1 - x else x)
   else (if m.fy then (w : Int) - 1 - y else y)) + m.dy
```

### The shape B

```lean
/-- The point `(a, b)` lies in the `s × s` square with corner at the origin. -/
def InSquare (s : Nat) (a b : Int) : Prop :=
  0 ≤ a ∧ a < s ∧ 0 ≤ b ∧ b < s

/-- The point `(a, b)` lies in the shape `B`: the `u × u` square at the origin or the `v × v`
square with corner `(ox, oy)`. -/
def InShape (u v : Nat) (ox oy a b : Int) : Prop :=
  InSquare u a b ∨ InSquare v (a - ox) (b - oy)
```

### Rookwise connected dissections

```lean
/-- Two cells of the `w × w` square are joined by rook steps inside the set `P`. -/
inductive RookPath (w : Nat) (P : Nat → Nat → Prop) : Nat → Nat → Nat → Nat → Prop
  | refl (x y : Nat) : RookPath w P x y x y
  | right {x y a b : Nat} : RookPath w P x y a b → a + 1 < w → P (a + 1) b →
      RookPath w P x y (a + 1) b
  | left {x y a b : Nat} : RookPath w P x y (a + 1) b → P a b → RookPath w P x y a b
  | up {x y a b : Nat} : RookPath w P x y a b → b + 1 < w → P a (b + 1) →
      RookPath w P x y a (b + 1)
  | down {x y a b : Nat} : RookPath w P x y a (b + 1) → P a b → RookPath w P x y a b

/-- A discrete dissection in the sense of exercises 88 and 89. The `w × w` square is colored with
at most four colors, and each color is rookwise connected. Each color has one motion, and the
motions give a bijection from the `w × w` square onto the shape `B`. The shape `B` is the `u × u`
square at the origin together with the `v × v` square whose corner is `(ox, oy)`, where `u < ox`.
So the two squares are separated by at least one empty column. -/
structure RookDissection (u v w : Nat) (ox oy : Int) where
  piece : Nat → Nat → Fin 4
  motion : Fin 4 → Motion
  connected : ∀ x y x' y', x < w → y < w → x' < w → y' < w → piece x y = piece x' y' →
    RookPath w (fun a b => piece a b = piece x y) x y x' y'
  maps_into : ∀ x y, x < w → y < w →
    InShape u v ox oy ((motion (piece x y)).imgX w x y) ((motion (piece x y)).imgY w x y)
  injective : ∀ x y x' y', x < w → y < w → x' < w → y' < w →
    (motion (piece x y)).imgX w x y = (motion (piece x' y')).imgX w x' y' →
    (motion (piece x y)).imgY w x y = (motion (piece x' y')).imgY w x' y' →
    x = x' ∧ y = y'
  surjective : ∀ s t : Int, InShape u v ox oy s t →
    ∃ x y, x < w ∧ y < w ∧
      (motion (piece x y)).imgX w x y = s ∧ (motion (piece x y)).imgY w x y = t
```

### The target

```lean
/-- **Target theorem for `(u, v, w)`**: exercise 89 has a negative answer for this triple. The two
squares are kept apart by at least one empty column, which is one way to keep them separate. -/
def NoRookDissection (u v w : Nat) : Prop :=
  ∀ ox oy : Int, (u : Int) < ox → RookDissection u v w ox oy → False
```

## Points to check in this formalization

- **At most four pieces.** Colors are `Fin 4`, and a color may be empty.
- **Each piece has one motion**, which is any of the eight symmetries with any integer shift.
- **Bijection.** `maps_into`, `injective` and `surjective` say exactly that the motions give a
  bijection from the `w × w` square onto `B`. Coordinates outside the square do not matter, because
  every condition is restricted to `x < w`, `y < w`.
- **Placement of the two squares.** The theorem is stated for every `ox > u` and every `oy`, so the
  `v × v` square is to the right of the `u × u` square, with at least one empty column between them.
  This is a way to keep the two squares separate, and one such placement would already be enough.
  Answer 87 of the fascicle also keeps them separate, by using `[x, y]` for one square and `⟨x, y⟩`
  for the other. Placements where the squares touch, or meet only at a corner, are not covered.
- **Rookwise connectivity.** `RookPath` is a path of rook steps inside the piece, within the
  `w × w` square.
- **No assumption on `gcd(u, v)`** is made.

## A stronger statement

For `(20, 21, 29)`, `(40, 42, 58)` and `(48, 55, 73)` the proof goes through this form, where
connectivity is not assumed, and the stronger theorems `no_dissection_20_21_29`,
`no_dissection_40_42_58` and `no_dissection_48_55_73` are proved. A piece here may be disconnected,
but all its cells must go to one square. This is the `[x, y]`, `⟨x, y⟩` form of answer 87.
Disconnected pieces that jump between the two squares are not covered.

**This stronger form is not proved for `(28, 45, 53)` and `(33, 56, 65)`.** The search that came
before this proof, which is not part of this repository, found disconnected dissections of this
form for those two triples. So their proofs use connectivity, as explained in
[How connectivity is used](#how-connectivity-is-used).

The step from `NoDissection` to `NoRookDissection` is `noRook_of_no` in
[`Ex89/Rook.lean`](Ex89/Rook.lean). A motion moves rook neighbors to rook neighbors, and the empty
column cannot be crossed by a rook step. So the image of a rookwise connected piece lies in one
square. Moving the `v × v` square by `(-ox, -oy)` then gives a `Dissection`.

```lean
/-- A four-piece dissection of the `w × w` square into two separate squares of sides `u` and `v`.
`toU k` says that piece `k` goes to the `u × u` square, and otherwise it goes to the `v × v` square.
A piece may be disconnected or empty, but all its cells use one motion and go to one square. -/
structure Dissection (u v w : Nat) where
  piece : Nat → Nat → Fin 4
  motion : Fin 4 → Motion
  toU : Fin 4 → Bool
  maps_into : ∀ x y, x < w → y < w →
    InSquare (if toU (piece x y) then u else v)
      ((motion (piece x y)).imgX w x y) ((motion (piece x y)).imgY w x y)
  injective : ∀ x y x' y', x < w → y < w → x' < w → y' < w →
    toU (piece x y) = toU (piece x' y') →
    (motion (piece x y)).imgX w x y = (motion (piece x' y')).imgX w x' y' →
    (motion (piece x y)).imgY w x y = (motion (piece x' y')).imgY w x' y' →
    x = x' ∧ y = y'
  surjective : ∀ (b : Bool) (s t : Int), InSquare (if b then u else v) s t →
    ∃ x y, x < w ∧ y < w ∧ toU (piece x y) = b ∧
      (motion (piece x y)).imgX w x y = s ∧ (motion (piece x y)).imgY w x y = t
```

```lean
/-- **Stronger form**: no four-piece dissection at all, connected or not, as long as each piece
goes to one square. -/
def NoDissection (u v w : Nat) : Prop := Dissection u v w → False
```

## The definitions have examples

[`Ex89/Witness.lean`](Ex89/Witness.lean) gives the rookwise connected dissection of the `5 × 5` square
into `3 × 3` and `4 × 4` squares as a value of `RookDissection 3 4 5 4 0`, and from it a `Dissection
3 4 5`. So neither structure is empty for a trivial reason. The kernel checks this without
`native_decide`, and `rook_nonempty` depends only on `propext` and `Quot.sound`. It follows that
`checkAll 3 4 5 ≠ true` (`checkAll_3_4_5`), also without `native_decide`.

One example does not prove that the definitions are right. They still have to be read.

## How connectivity is used

For `(28, 45, 53)` and `(33, 56, 65)`, the search `checkR` in
[`Ex89/RookCheck.lean`](Ex89/RookCheck.lean) is `checkAll` with one more test
for each placement of the four pieces that propagation cannot refute. The test is in
[`Ex89/Match.lean`](Ex89/Match.lean). It has three rules.

- **Potentials.** Give numbers to the source cells and the target cells, such that along every
  possible edge the number of the target is at most the number of the source. Summing along the true
  bijection shows that the sum over the targets is at most the sum over the sources, and that no true
  edge has a slack larger than the difference. This contains Hall's condition, and also the removal
  of the edges that lie in no perfect matching.
- **Connectivity.** A set of cells that contains the corner of a piece and is closed under rook steps
  inside the possible cells of that piece contains the whole piece. A variant of this rule with one
  cell left out shows that a cell that separates the corner from a cell of the piece is in the piece.
- **Branching** on the piece of one cell.

These rules need no planarity argument. The numbers, the closed sets and the cells come from
[`Ex89/Oracle.lean`](Ex89/Oracle.lean), which computes a matching, strong components, breadth-first
search and cut vertices. Nothing is proved about that file, and nothing needs to be: `TA.rookDead`
holds for every oracle, because every answer is checked before it is used. A wrong answer can only
make the test weaker.

The test is needed for few placements: 12 for `(28, 45, 53)` and 26 for `(33, 56, 65)`.

## Trust

The search is run by `native_decide`, which compiles the search to native code and runs it. The Lean
kernel does not repeat this computation. `#print axioms` gives this output for the two theorems of
`(20, 21, 29)`. The theorems of the other triples give the same output with their own `check_…`:

```
[propext, Classical.choice, Quot.sound, Ex89.check_20_21_29._native.native_decide.ax_1_1]
```

The last axiom is generated by `native_decide`. The build prints its statement:

```
axiom Ex89.check_20_21_29._native.native_decide.ax_1_1 : decide (Ex89.checkAll 20 21 29 = true) = true
```

So the proof trusts the Lean compiler, the C compiler and linker that build the native code, the Lean
runtime, and the machine, in addition to the kernel. The kernel checks all other steps. Those include
the theorem `no_dissection_of_check` in [`Ex89/Normal.lean`](Ex89/Normal.lean), which says that
`checkAll u v w = true` implies `NoDissection u v w` when `0 < u`, `0 < v`, `u < w` and `v < w`. The
theorem needs no other assumption on `(u, v, w)`. In the same way, `no_rook_of_check` in
[`Ex89/RookCheck.lean`](Ex89/RookCheck.lean) says that `checkR u v w = true` implies
`NoRookDissection u v w`.

Three parts of the compiled program are not seen by the proofs, and they are also trusted through
`native_decide`:

- `persist` in [`Ex89/Check.lean`](Ex89/Check.lean) is the identity function for the kernel. Through
  `unsafe` and `implemented_by`, the compiled program also calls `Runtime.markPersistent`, so that
  shared values do not have their reference counts updated. Without it the threads spend most of
  their time fighting over those counts.
- `Task.spawn` runs the search in parallel. The proofs treat it as the plain computation.
- [`Ex89/Oracle.lean`](Ex89/Oracle.lean) uses `partial`. The proofs do not depend on its results, so a
  bug there can only make the search fail or not terminate.

The search program is [`Ex89/Check.lean`](Ex89/Check.lean). As a regression test, `native_decide`
refuses `checkAll u v w = true` for `(3, 4, 5)`, `(6, 8, 10)` and `(8, 15, 17)`, and `lake exe gate4 u v w`
reports `checkR u v w = false` for `(3, 4, 5)`, `(6, 8, 10)`, `(9, 12, 15)` and `(8, 15, 17)`. This
shows only that the search does not accept those triples. The evidence that the definitions have
examples is in [the section above](#the-definitions-have-examples).
